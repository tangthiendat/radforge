## Scope

In:

- v1.4.3 is the next patch release after v1.4.2
- GitHub release assets are the distribution boundary for scripts, archives, and checksum files
- the existing `RADFORGE_ARCHIVE_URL` override remains supported only with an explicit matching checksum or checksum URL

## Validation Strategy

- ordered checks from narrowest to broadest:

  - run: script parser and POSIX syntax checks
  - expected: zero parse errors and zero syntax exits
  - if it fails: correct syntax before runtime tests

  - run: isolated local lifecycle and checksum-rejection tests
  - expected: valid artifacts pass; invalid hashes fail before extraction
  - if it fails: inspect bootstrap verification and state handling

  - run: build and verify release assets from the tagged tree
  - expected: every asset has a matching SHA-256 file
  - if it fails: do not publish

  - run: download and exercise published v1.4.3 assets
  - expected: documented install/uninstall path succeeds remotely
  - if it fails: keep the release unannounced and repair asset naming or bootstrap URLs

- lowest useful validation first: yes; parsing and isolated homes catch defects before any external release mutation

## Risks And Approval Points

- release URLs must not be documented until matching assets are published
- a custom archive override without a trustworthy checksum must fail closed
- publishing v1.4.3 is approved; unrelated refactors, CI, or state-schema changes remain out of scope
